## Design

**Runtime seam.** `Runtime` protocol = the `DockerService` operations above; `Handle` protocol = the handle uses above,
with full signatures and backend-neutral errors (`HandleGone` replacing `NotFound` at call sites; `DockerRuntime` maps
`docker.errors.NotFound` to it). Image resolution, the `_images.py` checks and `_docker_preflight.py` live behind the
Docker boundary. Backend selection is `args.runtime_backend` (`--runtime {docker,process}`, `GRAPH_LOADER_RUNTIME`),
default `docker`, honoured by `start`, `stop`, `status`, `replay-dlq`.

**Launch.** `ProcessRuntime` starts `[sys.executable, "-I", "-u", "-m", "neo4j_graph_loader._child", <role>, <args>]`
with `subprocess.Popen(start_new_session=True, close_fds=True, pass_fds=(control_fd,), cwd=<run-dir>/work/<role>-<n>,
env=<allowlist>)`. `-I` makes the interpreter ignore every `PYTHON*` variable and the user site; no `preexec_fn` (the CLI
is multithreaded). Environment allowlist: `PATH`, `HOME`, `LANG`, `LC_ALL`, `TZ`, `TMPDIR`, plus exactly the per-role
variables the Docker mode builds today; nothing else is inherited.

**Control channel and readiness.** One socketpair per child. The child wrapper applies `LOADER_CPUSET`
(`os.sched_setaffinity`), then imports and starts the role; the role module calls a new `runtime_ready(bound_ports=…)`
hook *after* its signal handlers are installed and its servers are bound, which sends a ready message with the actual
bound ports. Until ready, a stop request is deferred exactly as Docker mode defers until `docker top` passes; a child that
exits before ready is a launch failure; a child not ready within the role's existing startup budget is killed and fails
the launch (negative controls for all three).

**Bare-process lifeline (host shape, CLI killed outside any manager).** EOF on the control socket (the CLI died, including
`kill -9`) makes the wrapper deliver `SIGTERM` to its own role, so the existing graceful shutdown runs, then exit hard
after a bounded deadline. This guarantee is only for the bare host shape; see "Managed shapes".

**Planner workers.** The CLI's planner multiprocessing workers and helper processes are registered and covered by the
same lifeline: each worker watches a parent-death pipe in a thread independent of its command loop, so a long scan is
interrupted, and the CLI stops planners before signalling any process group so ordered planner cleanup is not pre-empted.
`tini -g` is therefore not used (see single container).

**Signalling without races.** Every signal goes through a pidfd (`os.pidfd_open` + `signal.pidfd_send_signal`): the CLI
opens the pidfd at spawn time, before any reap. Process-group signals (`killpg`) are only sent by the CLI to groups whose
leader it has not yet reaped (an unreaped leader keeps the PGID from being reused). A second shell's `stop` never signals
roles: it opens a pidfd to the registered **CLI**, verifies `/proc/<pid>/stat` start time and boot id *after* opening it,
and sends `SIGTERM` through that pidfd, so the CLI performs its normal ordered stop.

**Registry.** Append-only JSONL in the run directory, one record per event (`intent` before spawn, `started` with pid,
pgid, start time, boot id, command digest, ports; `ready`; `exit` with code), each line carrying a checksum and `fsync`ed;
a torn tail line is ignored on read. Before any further append after a failed or short write, the writer (under its lock)
truncates back to the last complete record, or marks itself broken and refuses appends, so a torn record can never become
interior damage (the pattern in `tests/installed_service/live_stack.py:58`). If the `started` write fails, the CLI kills the child through its held pidfd and fails the
launch. Concurrent stop and reap are serialized in the CLI (single owner per handle). Exit receipts are terminal.

**Exit codes.** Negative `returncode` (signal *n*) is reported as `128 + n`, matching Docker (`137` after the stop grace).
`stop(timeout)` = `SIGTERM`, wait `timeout`, `SIGKILL`, the same grace Docker mode passes to `container.stop`.

**OOM.** Process mode never claims a per-child OOM victim. The handle's `OOMKilled` is `None` ("unknown"); in a cgroup v2
container or service the runtime records a run-level event when `memory.events` `oom_kill` rises, and the failure message
says "cgroup OOM kill observed; victim unknown" when a child died by `SIGKILL` in that interval. Call sites that read
`OOMKilled` treat `None` as unknown (S1 adds this to the protocol; Docker mode keeps its bool).

**Addresses.** Lease server and dispatcher bind `127.0.0.1` on a port the runtime reserves per run; the lease-server
replacement the current code performs rebinds the *same* port (`allow_reuse_address`) so `GRAPH_LOADER_BUCKET_LEASE_ADDR`
stays valid. A failed rebind within the existing replacement budget fails the run with the Docker mode's error class.

**Metrics and health.** In process mode each role binds its metrics on `--metrics-addr` (default `127.0.0.1`) and port 0,
passed through the explicit `port=` API argument (the environment-variable path rejects 0 and falls back to 9464,
`metrics.py:719`); the actual port arrives in the ready message; the CLI rewrites a Prometheus `file_sd` JSON atomically on every start,
replacement and exit. A metrics bind failure keeps today's "metrics unavailable, role keeps writing" behaviour but is
recorded in `file_sd` and the CLI log. `--health-addr` serves `/healthz` (CLI loop alive) and `/readyz` (fleet ready, every
required role running, no unrecovered failure). In the single container, targets are reachable only through the pod
address, so the docs set `--metrics-addr 0.0.0.0` there.

**Resources.** A shared memory limit covers every process in the container or service. Cgroup-aware sizing is **process
backend only**: the existing `available_memory_bytes()` / `default_plan_memory_mb()` and every public planner default stay
exactly as they are, so Docker mode is unchanged even when its CLI itself runs in a bounded container or service.
`ProcessRuntime` computes a process budget and passes it to the planner explicitly: effective headroom = the minimum over
the leaf cgroup and every visible ancestor of (`memory.max` − `memory.current`), clamped at zero, further bounded by
`MemAvailable`, minus the reserved peaks of the roles it will launch. If the aggregate worker floor (workers × the existing
256 MiB minimum, `edge_planner.py:153`) does not fit, it reduces planner concurrency, and if one worker does not fit it
refuses the launch with a sizing error. The docs give sizing as CLI + planners + Σ(role peak RSS) from measurements; when
no limit can be read, process mode requires explicit planner worker/memory settings.

**Managed shapes.** Inside a container, the CLI's death ends the container (Tini exits with its child; PID 1 exit kills the
namespace), and under systemd `KillMode=mixed` sends `SIGKILL` to the rest once the main process is gone. These are the
managers' semantics, not runtime defects. The guarantees there are: ordered shutdown on an ordinary `SIGTERM`/`docker
stop`/`systemctl stop`, and, after abrupt termination, safe restart with redelivery (at-least-once, idempotent writes,
no duplicate fleet). The bare-process lifeline guarantee is not claimed for managed shapes.

**Single container.** The CLI image adds `tini` (without `-g`) as PID 1; `docker stop`/pod termination sends `SIGTERM` to
the CLI only, which performs the ordered stop within the grace. Example Kubernetes manifests (a 1-replica Deployment for
stream, a Job for bulk) are documented as untested on a real cluster.

**Host service.** A documented systemd unit: `ExecStart=graph-loader start --runtime process …`, `KillMode=mixed`,
`TimeoutStopSec` = the CLI's stop budget plus margin, `Restart=on-failure` (systemd is the only restart owner; the member
wait after a restart is E13 finding B), `EnvironmentFile=` mode 0600, child logs relayed to stdout → journald.
`KillMode=control-group` (systemd's default) is documented as unsupported because it signals every child at once. The CLI
stays foreground-only (no daemonizing, no PID file).

**Logs.** Each child's stdout/stderr → `<run-dir>/logs/<role>-<n>.log` (size-capped rotation, the source of truth for
`handle.logs`), relayed non-blocking to the CLI's stdout with a `[role/n]` prefix (`--child-logs {relay,files}`).

**Unchanged.** Kafka/Neo4j semantics, consumer groups, DLQ, ordering, supervision policy, schema, public API.
