# E06 — Deliver checkout-free Docker execution

Plan review: **approved**. Implementation: **complete**.

**Outcome.** The installed CLI can launch matching components without local repository Dockerfiles.

**Scope.** Implement only the D06 deployment strategy. Construct candidates locally; registry/image publication still requires a separate user instruction.

**Prerequisites.** E05

**Exit gate.** A wheel-driven tiny load runs away from the checkout with the selected local candidate images/build context, explicit mount paths and reachable services.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

## Feature E06.F1 — Versioned component delivery

### Story E06.F1.S1 — Build and identify candidate component images

- Status: complete; estimate: 1 engineering day(s).
- Checklist: D4, P3.
- Story dependencies: E05.F2.S1.
- Change surface: Node/edge/coordinator or legacy clock images as required; image manifest; build contexts.
- Evidence: `../evidence/E06.F1.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Build every component advertised by the release with the approved namespace/version.
2. Record local image IDs or OCI archive hashes and compatibility metadata; propose registry tags/digests without pushing.
3. For bundled-build-context strategy, package a tested complete context and resolve it through resources rather than cwd.

**Validation**

- Build required images and inspect entry points/version labels; verify no context file is missing.

### Story E06.F1.S2 — Implement deterministic image selection and overrides

- Status: complete; estimate: 1 engineering day(s).
- Checklist: D4, D5.
- Story dependencies: E06.F1.S1.
- Change surface: DockerService.build_*; image selection/version compatibility; CLI skip-image-build behavior.
- Evidence: `../evidence/E06.F1.S2.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Default to approved matching versioned images or the approved bundled context; no implicit build from path=".".
2. Honor explicit image overrides with an explicit compatibility policy; missing/incompatible images fail clearly.
3. Define pull/build behavior and ownership; do not start Kafka/Neo4j as a side effect of pip installation.

**Validation**

- Run installed CLI outside checkout with preloaded images and --skip-image-build; test missing images, overrides and daemon-unavailable cases.

## Feature E06.F2 — Host/container contracts

### Story E06.F2.S1 — Verify mounts, coordinator reachability and remote services

- Status: complete; estimate: 1 engineering day(s).
- Checklist: D5, D6.
- Story dependencies: E06.F1.S2.
- Change surface: Docker launch networking/paths; preflight diagnostics; service configuration docs.
- Evidence: `../evidence/E06.F2.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Cover schema, rejection, plan/ledger/spill mounts plus writer↔dispatcher/lease and host↔coordinator addresses.
2. Exercise host/container Neo4j and Kafka addresses, advertised Kafka metadata, database selection and credential errors without logging secrets.
3. Document remote-daemon absolute-path requirements and supported Docker Desktop file-sharing/network behavior; unsupported scenarios fail clearly.

**Validation**

- Run a small installed-wheel/container load on the supported topology in an isolated database; assert graph, offsets and cleanup.
- Test remote-service configuration and bind-mount failures; installing the wheel alone starts no infrastructure.
