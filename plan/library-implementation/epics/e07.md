# E07 — Run regressions against installed artifacts

Plan review: **approved**. Implementation: **complete**.

**Outcome.** A reusable test path that cannot accidentally import application code from the checkout.

**Scope.** Keep test fixtures/reference helpers explicit; do not rewrite all tests or weaken assertions just to make packaging pass.

**Prerequisites.** E06

**Exit gate.** Wheel and sdist-built wheel pass the installed regression selection, with import provenance proven in parent and child processes.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

## Feature E07.F1 — Isolated runner and fixtures

### Story E07.F1.S1 — Create the installed-code test runner

- Status: complete; estimate: 1 engineering day(s).
- Checklist: V2, V5.
- Story dependencies: E06.F2.S1.
- Change surface: Test runner scripts/config; isolated test staging; test import provenance assertions; Proposed scripts/verify_installed.py CLI with --lane, --wheel and --inventory parameters.
- Evidence: `../evidence/E07.F1.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Stage tests and necessary maintained fixtures without src application files, .git or developer datasets.
2. Neutralize pytest pythonpath, sys.path shims, inherited PYTHONPATH and checkout-based subprocess cwd assumptions.
3. Verify imports resolve inside the target environment in both parent and child processes; keep editable checks separate.
4. Implement the runner interface used below: python scripts/verify_installed.py --lane <lane> --wheel <explicit-wheel-path> --inventory plan/library-implementation/test-inventory.json. It creates isolated staging/envs; it does not require plan files inside installed artifacts.

**Validation**

- Run from a temp directory using a fresh wheel install; deliberately omit a runtime module/resource and prove the runner detects the failure.

### Story E07.F1.S3 — Freeze the installed-test inventory and fixture closure

- Status: complete; estimate: 0.5 engineering day(s).
- Checklist: V5.
- Story dependencies: E07.F1.S1.
- Change surface: test-inventory.json; per-file classification of tests/** and example tests; helper/config closure manifest.
- Evidence: `../evidence/E07.F1.S3.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Start with the concrete core/safety/cli-runtime/service file lists in test-inventory.json; collect test IDs and compute recursive helper/config/fixture closure before porting.
2. Classify every remaining repository test file as an installed lane, E09 service lane, checkout-only development test with rationale, or a new bounded porting story. Retain the full checkout suite independently.
3. Inventory changes cannot silently reduce assertions or move difficult runtime regressions to checkout-only; split overflow into reviewed stories before starting an over-size lane. Resolve extra test dependencies without shipping them as runtime deps.
4. Before any port starts, record staged file/fixture counts, all collected test IDs (including parametrization), recursive helper/config closure and revised effort for each lane. If a lane exceeds its 1–1.5-day estimate, create smaller reviewed slices first; no undisclosed extra work or lost regressions.

**Validation**

- Compare pytest --collect-only results with the checked inventory and source baseline; verify reference_edge_planner, cross-test helpers, conftest, config/ and golden fixtures are classified/staged explicitly.
- Fail the inventory check when a selected file/test ID disappears or is deselected without a documented approved disposition.
- Compare the current initial inventory scale (fresh audit AST counts: core 253, safety 688, CLI/runtime 308 test functions before parametrization) to actual collected IDs and helper closure. These are discovery inputs, not test pass evidence or a requirement to rewrite every test.
