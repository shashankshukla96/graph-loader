# E11 — Freeze and rehearse a release candidate

Plan review: **approved**. Implementation: **not started**.

**Outcome.** Immutable artifact and image evidence plus a separately authorized TestPyPI rehearsal.

**Scope.** This epic includes future external actions only as gated stories. The current planning request and earlier no-push instruction authorize none of them.

**Prerequisites.** E10

**Exit gate.** Exact candidate wheel/sdist bytes, image identity, ownership, page inspection and retrieved-install checks are recorded; failures trigger a new candidate and revalidation.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

### Story E11.F1.S2 — Freeze source/version and build the exact package candidate

- Status: planned; estimate: 0.5 engineering day(s).
- Checklist: P3, V1, V2, V3, V4, V5, V6, T4.
- Story dependencies: E11.F1.S1.
- Change surface: Clean release snapshot; explicit artifact inventory; SHA-256 manifest; local image identities.
- Evidence: `../evidence/E11.F1.S2.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Freeze all scoped source, requirements, resources and package release notes at a clean reviewed candidate snapshot. Include formerly untracked prerequisite files in that source identity.
2. For SCM mode create the local candidate tag before all final builds; file-version mode records the tested candidate version/commit. No Git push is authorized.
3. Build wheel/sdist in an empty candidate directory, inspect/twine-check and record exact filenames/hashes, metadata and version. Do not reuse development build bytes by assumption. Final image construction and the final gates follow in S3.
4. Refreeze the distribution contract in test-inventory.json for the candidate with scripts/freeze_installed_inventory.py --freeze (E10 changed the wheel METADATA, so verify_installed.py refuses the current wheel until then); existing test IDs and dispositions stay unchanged and in order. Set the CHANGELOG release date to the freeze date (user decision 2026-11-01).

**Validation**

- python -m build; python -m twine check --strict on explicit candidate files; inspect inventories, metadata/license/version/entrypoints and private-file exclusions.
- Rebuild/install the sdist wheel without .git and validate version/resources. Record the source/dependency/build-input manifest for S3.

### Story E11.F1.S3 — Build final images and rerun the gates on the final candidate

- Status: planned; estimate: 2 engineering day(s).
- Checklist: D4, P3, V1, V2, V3, V4, V5, V6, T4.
- Story dependencies: E11.F1.S2.
- Change surface: Final component images from the frozen candidate; one candidate manifest binding source, packages, images and gate results.
- Evidence: `../evidence/E11.F1.S3.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Build every shipped component for linux/amd64 and linux/arm64 (D04) from the exact frozen E11 source/version, preferably installing the frozen wheel. Never carry forward E06/E09 development image IDs as final proof.
2. Assert package metadata, Python version API, executable --version, metrics version labels and image compatibility metadata agree according to the approved override policy. Record source commit/tag, wheel hash where installed, dependency/build-context hashes, local image IDs/OCI archive hashes.
3. Rerun the E07 installed lanes, the E08 support lanes and the E09 service lanes against the final wheel/sdist and final amd64 image identities, and an installed-CLI real-load smoke on arm64; earlier development-image passes are not the final gate. Preserve every pass, skip and exclusion reason.
4. Produce one manifest linking source commit/version, wheel/sdist filenames and hashes, image IDs and all gate results; any later change requires a new candidate and rerun of the affected gates.

**Validation**

- Build and start every final component with version/import/help checks; inspect labels and capture actual in-image runtime/dependency identities.
- Run the installed runner lanes with explicit manifest paths and final image identities; verify nothing comes from a stale dist directory or older image tag.

## Feature E11.F2 — Authorized external rehearsal

### Story E11.F2.S1 — Obtain approval and publish candidate images/TestPyPI files

- Status: planned; estimate: 0.5 engineering day(s).
- Checklist: D4, T4.
- Story dependencies: E11.F1.S3.
- Change surface: Explicit user publication instruction; exact artifact/image manifests; release command record.
- Evidence: `../evidence/E11.F2.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Present the concrete version, commit, files/hashes, image targets and test results; obtain a new explicit user instruction for the specific image and TestPyPI uploads.
2. Push only the validated images after authorization and record registry digests; verify content identity against the local candidates.
3. Upload exactly the manifested wheel/sdist bytes to TestPyPI; preserve no-push until specifically superseded and never infer PyPI production permission.
4. Only the frozen S3 manifest is uploadable.

**Validation**

- Use explicit image targets and explicit twine upload --repository testpypi <candidate-wheel> <candidate-sdist> after authorization.
- Re-pull images by digest and verify compatibility/content; changed image contents require renewed validation.

### Story E11.F2.S2 — Verify retrieved artifacts and index presentation

- Status: planned; estimate: 1 engineering day(s).
- Checklist: T5, T6, V2, V6.
- Story dependencies: E11.F2.S1.
- Change surface: TestPyPI download/hash record; isolated install results; rendered project-page checklist.
- Evidence: `../evidence/E11.F2.S2.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Retrieve the exact candidate version with --no-deps from TestPyPI, then install the reviewed dependency set from normal PyPI separately; never combine indexes via --extra-index-url.
2. Compare retrieved hashes; run pip check, public API/CLI/resource checks and a small real load using the published candidate images.
3. Inspect README/license/links/Python support/maintainers/files; defects require a new version/candidate and repeated affected gates.
4. Production release and E12 consume the frozen S3 manifest plus verified registry digests; never substitute development images.

**Validation**

- Download/install into a fresh virtualenv and unrelated cwd; record hashes, provenance and real-service result.
- Capture project-page checks; do not treat a no-deps install or skipped Docker test as full proof.
