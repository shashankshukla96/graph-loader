# E05 — Make CLI and resources independent of the checkout

Plan review: **approved**. Implementation: **not started**.

**Outcome.** An installed executable that accepts explicit inputs and uses writable runtime state outside the package.

**Scope.** Handle local files/resources and process entry behavior here; Docker image selection is E06.

**Prerequisites.** E04

**Exit gate.** Installed help/version/schema example work from an unrelated cwd, resources are complete, and state writes succeed with a read-only package directory.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

## Feature E05.F1 — Installed command and resource delivery

### Story E05.F1.S1 — Add executable and module entry points

- Status: planned; estimate: 0.5 engineering day(s).
- Checklist: P4, P3.
- Story dependencies: E04.F2.S2.
- Change surface: project.scripts; new CLI main/__main__; version flag.
- Evidence: `../evidence/E05.F1.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Use the approved executable targeting a no-argument-compatible function, with supported module invocation.
2. CLI --version agrees with metadata; help/version do not require services or a Docker connection.
3. Preserve command semantics, error exit codes and current explicit .env policy; do not silently load caller secrets on import.

**Validation**

- Install wheel and test help/version, parser errors and module/executable parity from an unrelated cwd with no services.

## Feature E05.F2 — Writable run state

### Story E05.F2.S1 — Define and thread runtime directories through launchers

- Status: planned; estimate: 1.5 engineering day(s).
- Checklist: A4, D5.
- Story dependencies: E05.F1.S2.
- Change surface: Runtime schema/rejection/plan/ledger/spill/progress/timing paths; CLI options/config; DockerService launch arguments.
- Evidence: `../evidence/E05.F2.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Use caller paths or documented writable defaults, never directories beside installed code.
2. Preserve ownership/permissions and distinguish host-side paths from paths visible to the Docker daemon.
3. Two separate runs do not collide; missing/unwritable paths fail clearly before ingestion.

**Validation**

- Test unrelated/read-only cwd, read-only package files, explicit temp directories, permission failures and concurrent runs.
- Inspect every container bind mount and generated runtime config path.
