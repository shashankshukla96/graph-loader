# E09 — Prove service behavior and ordering limits

Plan review: **approved**. Implementation: **not started**.

**Outcome.** Installed-artifact integration evidence for the supported modes and the exact promised guarantees.

**Scope.** Use throwaway services/scratch databases and the locally identified candidate images. The loaded remote IMDb graph is never a test fixture to reset.

**Prerequisites.** E08

**Exit gate.** Every supported mode and ordering case has an executed result with graph/offset/cleanup evidence; unsupported cases are explicitly documented and excluded from guarantees.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

- Change surface: ordering-matrix.md cases O1–O3; deterministic restart/revocation/eviction tests and isolated retry probes.
- Evidence: `../evidence/E09.F2.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**
