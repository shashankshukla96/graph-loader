# E03 — Migrate the Python namespace atomically

Plan review: **approved**. Implementation: **complete**.

**Outcome.** The complete loader runs under the approved distinctive namespace.

**Scope.** Preserve algorithms, Kafka keys/groups, formats and exit codes. Treat the mechanical rename as one cohesive integration change, not independently releasable half-moves.

**Prerequisites.** E02

**Exit gate.** Full checkout suite passes under the new namespace, all first-party entry paths work, and the built wheel contains complete migrated code with no accidental top-level src package.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

## Feature E03.F1 — Cohesive mechanical migration

### Story E03.F1.S1 — Move modules and every executable reference together

- Status: complete; estimate: 2 engineering day(s).
- Checklist: P1, P4, A6.
- Story dependencies: E02.F1.S2, E02.F2.S1.
- Change surface: src package tree → src/<import_name>/; tests; examples; Dockerfiles; Makefile/scripts; module invocation strings; pyproject.toml pytest bootstrap; development install instructions; Dockerfile and all component Dockerfiles.
- Evidence: `../evidence/E03.F1.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. In one cohesive change move runtime modules and update Python imports, test imports, monkeypatch/sys.modules targets, pickle-visible source classes, subprocess commands and container entry points.
2. Update executable example imports and runtime config/resource references; keep test fixture/reference modules out of the runtime namespace.
3. Retain regression behavior and schema/message/group identities; do not mix algorithm rewrites into the rename.
4. Choose a documented editable install for checkout development (python -m pip install -e .) and remove the root-only pytest path workaround as appropriate; install the renamed package before running checkout suites. Editable checks do not count as installed-artifact validation.
5. Update every existing Dockerfile in this same atomic migration so the renamed package is immediately importable: install the package with reviewed dependency inputs and source-layout discovery (preferred), or explicitly use the correct source root during this development transition. Entry-point renames or a successful docker build alone are insufficient. Supply a backend-compatible version for SCM builds lacking .git.

**Validation**

- In a fresh development virtualenv: install the declared development tools/dependencies, python -m pip install -e ., then python -m pytest tests examples/imdb/tests -m "not integration and not smoke" -q. Record resolved paths and preserve baseline behavior.
- Search tracked executable files for old imports/module and monkeypatch targets; keep a classified residual inventory.
- Build Dockerfile plus each required component Dockerfile, then docker run --rm --entrypoint python <local-component-image> -c "import <import_name>; print(<import_name>.__file__)" and docker run --rm --entrypoint python <local-component-image> -m <import_name>.<component_module> --help. Test node, edge, retry, dispatcher, lease and legacy clock entry modules only where supported; no services required for help.

## Feature E03.F2 — Migration compatibility and artifact integrity

### Story E03.F2.S1 — Implement the approved old-namespace policy

- Status: complete; estimate: 0.5 engineering day(s).
- Checklist: P1, U4.
- Story dependencies: E03.F1.S1.
- Change surface: Compatibility policy and optional narrowly scoped shims; migration tests.
- Evidence: `../evidence/E03.F2.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Use exactly the E01 shim policy: remove old src imports or provide explicitly temporary aliases with a sunset.
2. Never accidentally package an unapproved generic src namespace; if aliases exist, avoid duplicate class identities, metrics registries or process state.
3. Document old-to-new commands/imports and test the chosen behavior.

**Validation**

- Install wheel away from checkout and test old/new import expectations in separate fresh processes; check class identity if shims are selected.

### Story E03.F2.S2 — Prove the migrated wheel includes all runtime modules

- Status: complete; estimate: 0.5 engineering day(s).
- Checklist: P1, P5.
- Story dependencies: E03.F2.S1.
- Change surface: Package discovery; wheel/sdist inventories; namespace inventory check.
- Evidence: `../evidence/E03.F2.S2.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Installed schema, planner and CLI modules import successfully without legacy checkout files.
2. All component module commands needed by images resolve from their new names.
3. No source-path insertion or editable install supplies application code for this artifact smoke check.

**Validation**

- Build and install a local wheel into a clean virtualenv; verify module.__file__ paths and component help commands from an unrelated cwd.
- Install a built wheel in a second clean environment with no editable install/PYTHONPATH, then smoke every shipped component module inside the newly built component images; assert no legacy checkout root provides imports.
