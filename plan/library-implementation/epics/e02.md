# E02 — Create the distribution foundation

Plan review: **approved**. Implementation: **complete**.

**Outcome.** An explicitly incomplete, locally buildable distribution scaffold and authoritative dependency metadata.

**Scope.** Only the new namespace/version scaffold ships at this stage; the legacy loader continues to work from the checkout. No installed CLI or usable public loader is claimed yet.

**Prerequisites.** E00, E01

**Exit gate.** A local scaffold wheel/sdist builds with correct metadata; dependency parity passes and checkout behavior remains green. This artifact is development-only and must not be uploaded.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

## Feature E02.F1 — Build metadata and dependency authority

### Story E02.F1.S1 — Add backend metadata and namespace/version scaffold

- Status: complete; estimate: 1 engineering day(s).
- Checklist: P1, P2, P3.
- Story dependencies: E00.F2.S1, E01.F2.S2.
- Change surface: pyproject.toml; proposed src/<import_name>/__init__.py and version module; LICENSE; build-tool dependency declaration.
- Evidence: `../evidence/E02.F1.S1.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Use approved names and backend with explicit discovery selecting only the new namespace scaffold.
2. Add README, URLs, Python requirement, SPDX/license-files and development version; do not advertise unsupported platforms.
3. Define one version authority with sdist-safe behavior; the scaffold must not import legacy src or configure logging/services.

**Validation**

- Build scaffold wheel/sdist in isolation and inspect metadata, license, file list and package version.
- Import the scaffold from a clean virtualenv away from the checkout; retain checkout regression checks.

### Story E02.F1.S2 — Centralize runtime requirements without silently changing bounds
