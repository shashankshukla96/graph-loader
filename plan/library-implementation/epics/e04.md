# E04 — Stabilize the small public library API

Plan review: **approved**. Implementation: **complete**.

**Outcome.** Approved schema/planning interfaces with documented ownership and controlled process effects.

**Scope.** Export only the E01 API. Scheduling workers, CLI supervision and test injection hooks remain internal unless explicitly approved.

**Prerequisites.** E03

**Exit gate.** Public API and lifecycle regressions pass, imports are inert and no unapproved retry/fleet guarantees are exposed.

Epic prerequisites apply to every story, in addition to the story-specific dependencies below. Estimates are rough focused engineering effort, not elapsed-time commitments. Story completion requires its acceptance criteria, validation, and evidence; implementing a file alone is insufficient.

### Story E04.F2.S5 — Implement owned deadline-aware framed worker transport

- Status: complete; estimate: 1.5 engineering day(s).
- Checklist: A2, A3.
- Story dependencies: E04.F2.S1.
- Change surface: Private parent/child IPC adapter used by _ProcessWorker and _planner_worker_main; internal framing/read/write protocol; supervised transport fault fixtures.
- Evidence: `../evidence/E04.F2.S5.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. After D02 approves the cancellation contract, use an owned socketpair/stream adapter (or a separately reviewed equivalent) with explicit length framing and parent-side nonblocking reads AND writes. Readiness never means a whole frame: accumulate header/body incrementally and wait for more bytes only through deadline/cancellation-aware selector slices. Do not call blocking Connection.recv(), send(), or sendall() on the coordinator after the deadline begins.
2. Preserve existing worker result types and external Kafka/plan formats. Specify frame-length/resource limits and clear failures for oversize, truncated, corrupt or EOF frames; document parent-side codec computation separately from bounded I/O waits without silently excluding post-submission IPC.
3. Own both endpoints in the planner; close duplicate child endpoints promptly. No receiver/helper thread or process is required by this design, so cancellation must not create an orphan helper. Parent broadcasts and stop delivery use the same bounded write path; if a child will not read stop, escalate through the separate cleanup budget instead of blocking on send.
4. Keep original initial submission/source-pickling exclusions explicit. Each advertised platform must support and test the chosen nonblocking socket transport; otherwise restrict that process-transport claim in D04. If implementation discovery needs a different ownership/transport design or exceeds this slice, split/re-review before coding.

**Validation**

- Test partial headers, partial bodies, frames larger than socket buffers, EOF/truncation and write backpressure on the private adapter with fake clocks/readiness controls; prove every wait rechecks its supplied cancellation signal and absolute deadline.
- Use real-process private-adapter fixtures for a worker that begins a valid reply larger than the socket buffer, exposes partial readiness and stalls, and a worker that stops reading later commands/stop frames. Exercise transport-level signal/deadline exits for both receive and send; assert the private adapter reports its interruption/failure promptly. An external supervisor enforces an independent hard deadline and owns fixture child/endpoint cleanup so regressions cannot hang pytest.
- This story gates private transport behavior and fixture ownership only. Public planner signatures/errors and partial-frame/backpressure integration controls are delivered by E04.F2.S3; complete operation elapsed-budget, liveness, marker and resource guarantees are gated by E04.F2.S4. Keep all negative controls in those successor gates.

### Story E04.F2.S3 — Implement bounded process-worker waits and cancellation

- Status: complete; estimate: 1.5 engineering day(s).
- Checklist: A2, A3.
- Story dependencies: E04.F2.S5.
- Change surface: Public planner/convenience API signatures; _ProcessWorker.recv and parent gather/broadcast waits; cancellation-contract.md.
- Evidence: `../evidence/E04.F2.S3.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Implement the D02-approved proposal in cancellation-contract.md: parent-only cancel_event and optional timeout_seconds, with distinct approved cancellation/timeout errors. If D02 selects a materially different design, revise this story before coding.
2. Integrate E04.F2.S5 complete-frame transport with parent gather/broadcast/result processing: bounded nonblocking I/O slices (target <=100 ms) check cancellation and the one absolute deadline during headers, bodies and write backpressure, not just before a blocking recv. Cancellation must not mutate caller start methods/signals.
3. Inline sources execute synchronously: cancellation/deadlines are cooperative between records/phases; arbitrary blocked next(), source construction, pickling, client callbacks or OS-uninterruptible work are explicitly outside interruption guarantees. Process mode is required when callers need to stop a blocked records() worker.
4. Use one operation-wide absolute monotonic deadline across all planning phases, never reset per gather/phase. Process-mode clock starts once initial task serialization/submission completes; inline-mode clock starts immediately before the first source iteration so the scan is included. Record it once and check between inline records. Kafka admin, source construction/pickling, arbitrary blocked next()/callbacks and OS-uninterruptible operations retain their explicitly documented exclusions.

**Validation**

- Through public imports, use a real child source that blocks after task submission plus deterministic fake-clock waits: cancellation/timeout is observed within poll tolerance; ordinary source errors retain their diagnostic cause.
- Test cooperative inline cancellation and explicitly document/test the unsupported inline-blocking boundary; never write a test that waits forever to prove it.
- Use fake clocks and a multi-phase source to prove expiry accumulates across scan/hub/emit rather than resetting; prove inline scan time is included from the first iteration and the process clock anchor is the completed initial submission.
- With an inline source yielding ten individually returning records and advancing a fake monotonic clock on each record, assert a short timeout interrupts the scan before all ten records are consumed, not only after initial submission. Separately assert time between a completed process start() and later finish() counts toward the same stored deadline.
- Through public planner imports, separately supervise real-process partial-large-reply stalls and later-command write backpressure, testing both cancellation and timeout. Assert the approved public error and prompt coordinator signal/deadline observation using the existing abort/terminate path. The supervisor has an independent hard deadline and owns emergency fixture cleanup; private-adapter tests alone do not satisfy this gate. E04.F2.S4 supplies the final total elapsed-budget, complete liveness, marker and resource assertions across these same public cases.

### Story E04.F2.S4 — Apply a bounded cleanup budget after cancellation/failure

- Status: complete; estimate: 1 engineering day(s).
- Checklist: A2.
- Story dependencies: E04.F2.S3.
- Change surface: Worker close/terminate/kill paths; parent finally cleanup; output failure markers and owned spill state.
- Evidence: `../evidence/E04.F2.S4.md` (create when executing, exclude secrets).

**Acceptance criteria**

1. Define one overall cleanup deadline (proposed configurable internal 10-second budget, chosen/tested within D02) across supported workers rather than N unbounded joins; signal workers first, then bounded join/terminate/kill as supported by the approved platform.
2. For normal spawned Python workers a cancelled/expired operation raises its public error after bounded cleanup. If the OS cannot reap a worker, report its identity and retain potentially live spill/ownership resources rather than falsely deleting another active owner; do not claim universal termination of OS-uninterruptible work.
3. Topic/file ownership and failure markers remain correct on source error, partial startup, cancellation and timeout; all normal test workers terminate and resources are reclaimed.
4. Transport endpoint closure and stop messages inherit E04.F2.S5 ownership/bounded writes; never wait indefinitely for a partial reply or full stop socket. No transport helper is introduced. Include partially transmitted reply/command cases in cleanup proofs; preserve potentially live state if a worker cannot be reaped.

**Validation**

- Test <=4 representative spawned workers including a blocked source, partial startup and a termination-resistant fake process; assert poll+cleanup budget with tolerant wall-clock bounds.
- For each advertised worker count/platform in E08, validate the shared budget and unresolved-resource diagnostics. Do not close the API gate on a documentation-only bounded-shutdown claim.
- Complete the public integration controls from E04.F2.S3 with final error/diagnostic, total poll-plus-cleanup elapsed-budget, worker/endpoint liveness, absence of leaked helpers, failure-marker and retained/reclaimed owned-resource assertions. Cover pre-reply blocked source, mid-frame reply stall, later-command/stop write backpressure, ordinary source failure and partial startup; exercise both timeout and cancellation where applicable. Keep an independent hard-deadline supervisor with emergency cleanup, and prove normal children exit while an unreapable-worker fake retains potentially live resources and reports their identities.
