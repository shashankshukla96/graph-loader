## Behaviour

* **Package data = checkout tree.** `src/neo4j_graph_loader/monitoring/` is a byte-for-byte copy of `monitoring/` (every non-`.py` file); `test_packaged_assets_equal_the_checkout_monitoring_tree` enforces it and prints the sync command. `test_the_asset_listing_matches_the_files_and_pyproject_names_every_pattern` checks every asset is matched by a `pyproject.toml` pattern and by `MANIFEST.in`.
* **`graph-loader monitoring export --out DIR --discovery {docker,file,kubernetes,static}`** with `--scrape-interval`, `--job-name`, `--extra-labels`, `--metrics-port`, `--targets`, `--targets-file`, `--docker-network`, `--namespace`, `--service-name`, `--prometheus-url`, `--datasource-uid`, `--values FILE`, `--force`. Everything is validated before anything is written; existing files are never overwritten without `--force`; exit 0/1, errors as `stage=monitoring reason=...`.
  * `prometheus/scrape-config.yml` + a minimal complete `prometheus/prometheus.yml` (what promtool checks). Every job sets `honor_labels: true`. docker: the shipped Docker SD job (network configurable); file: `file_sd_configs` on the targets file; static: the aggregated endpoint (`--metrics-port`, optional `--targets`); kubernetes: `kubernetes_sd_configs` (endpoints role, keep on the Service label and the `metrics` port name). Extra labels become `relabel_configs` replacements on every job.
  * `kubernetes/{service,servicemonitor,podmonitor}.yaml`: Service and monitors select the same label, the port is named `metrics` and equals `--metrics-port` (targetPort too), `honorLabels: true`, the scrape interval and the extra labels as relabelings.
  * `prometheus/alerts/*.yml` from the shipped text. With no values and the default job the output equals the shipped files exactly (comments included: `test_defaults_reproduce_the_shipped_alert_rules_exactly`); with `--values` only the named parts change.
  * `prometheus/alert_tests/`: the shipped promtool tests when nothing was customised, plus `generated_test.yml` always: boundary tests of every overridable threshold built from the FINAL values (see below).
  * `grafana/dashboards/graph-loader-overview.json`: `__inputs` (a Prometheus datasource input), the datasource variable defaulting to it, `$__rate_interval` instead of the fixed `[1m]`/`[5m]` windows; `grafana/dashboards-sql/graph-loader-run-history.json`: the PostgreSQL run-history dashboard with its own `DS_POSTGRES` input and `pg_datasource` variable (executions, failed, active, per-hour by state, executions table, failures with outcome, roles/incarnations and events of the selected execution; every table it reads is asserted to be in the SQL schema); provisioning files with `--datasource-uid`/`--prometheus-url`; `BUNDLE.md`; `manifest.json` (options and sha256 of every file).
* **Values file** (`--values`): `job_name`, `labels` (added to every alert), `disable: [alert...]`, `alerts: {Name: {threshold, for, severity}}`. Unknown keys, unknown alerts, thresholds on alerts without one, non-positive/non-numeric/boolean thresholds, bad durations and severities are errors, never ignored. Overridable thresholds (7): WriteOutage (120 s), DlqBacklogHigh (100), RetryStalled (600 s), ConsumerLagHigh (100000), ConsumerLagCritical (1000000), RetryRateHigh (1/s), PlanResourceWaitHigh (5 s); a test pins each default to the literal in the shipped rule so a drifted default cannot make an override miss. An overridden alert gets one comment line (`# exported with threshold 300 (default 120), ...`); threshold text in summaries follows (`more than 2/s`, `exceeded 8s`). Disabling every alert of a group drops the group, and of a file drops the file.
* **`--extra-labels` / `labels`** reject the four reserved identity names (`run_id`, `execution_id`, `exporter`, `runtime`) and the names Prometheus or the exporters already set (`job`, `instance`, `kind`, `name`, `le`, `quantile`, `role`), `__*` and invalid names, empty or multi-line values (command: exit 1, nothing written).
* **Bundled quick-start stack (D15-2).** Prometheus and Grafana bind `127.0.0.1` by default; Grafana's admin password is required (`${GRAFANA_ADMIN_PASSWORD:?...}` in Compose, so a bare `compose up` also fails; `make monitoring-up` additionally rejects an empty value, `admin` and fewer than 8 characters before creating any directory); `make monitoring-down` supplies a placeholder because Compose interpolates the whole file for every subcommand, so it never needs the password; anonymous access is opt-in (`GRAFANA_ANONYMOUS_ENABLED`). The stack mounts `${MONITORING_DIR:-./monitoring}`: the checkout tree (= the packaged bundle) by default, or an export (`make monitoring-bundle`, optional `MONITORING_VALUES`) for your own thresholds. The live proof (rejection on the real Compose, loopback binds, down without the password) is S12.
