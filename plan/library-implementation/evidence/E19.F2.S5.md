# E19.F2.S5 — Mirror-aware Dockerfiles and secret transport (evidence)

Date 2026-11-03. Worktree `graph-loader-e19`. Nothing committed. Mac with Docker Desktop (already running), arm64, BuildKit v0.33.1 through `docker buildx` 0.37.2. Logs, results and the
server access logs are in `E19.F2.S5-logs/` (credentials redacted as `SENTINEL-REDACTED`). The harness is `plan/library-implementation/tools/e19_s5_proof.py` with
`e19_servers.py` (private; the owned index, Debian mirror proxy and sinks).

## Change

- Four Dockerfiles rewritten (`Dockerfile`, `Dockerfile.node_loader`, `Dockerfile.edge_loader`, `Dockerfile.clock`). They take everything from a generated context mounted at `/ctx`
  (`--mount=type=bind`, so no wheel, lock or wheelhouse becomes a layer): the package wheel, `lock.txt`, `install.py`, `pip-ca.pem` (possibly empty) and an optional `wheelhouse/`.
  Build arguments: `BASE_IMAGE` (default `python:3.12-slim`, used by the single `FROM ${BASE_IMAGE}`; no `# syntax=` line), `PACKAGE_WHEEL`, `PACKAGE_WHEEL_SHA256`, `DEPENDENCY_SOURCE`
  (`index-secret` | `index-url` | `wheelhouse`), `INDEX_URL` (no credentials), `INSTALL_FLAGS` (checks, e.g. `--probe-cmdline`), `GRAPH_LOADER_VERSION`, and for the CLI image `TINI_VERSION`, `DEBIAN_MIRROR`.
  No credential is a build argument; the URL is the BuildKit secret `pip_index` (`required=false`, so a wheelhouse build needs none).
- `src/neo4j_graph_loader/image_build/install.py` (stdlib only, run as `python -I`): fresh pip environment (`PATH`, `PIP_CONFIG_FILE=/dev/null`, `PIP_INDEX_URL`, `PIP_CERT` when a CA is given),
  `pip config list` in that environment must show exactly those `:env:` keys and values, the URL is read from the secret file by the helper and redacted from pip's output, the lock installs with
  `--require-hashes --only-binary=:all: --no-deps` from the index or `--no-index --find-links`, the package wheel must match its expected sha256 and installs by hash with `--no-index`, then `pip check`.
- CLI image: `tini` step with the skip path (a base image that already carries tini 0.19.0 skips apt) and the mirror path (`DEBIAN_MIRROR` replaces the Debian sources with a deb822 file for that mirror).
- The default `--config` of the role entry points (`config/graph_schema.yaml`, relative to `/app`) is copied from the installed package's bundled schema (byte-identical to the old `config/graph_schema.yaml`; a test asserts it).
- Tests: `tests/test_image_build_files.py` (23), `tests/test_image_install.py` (19 incl. one Linux-only), assertions updated in `test_candidate_images.py` and `test_dockerfile_single_container.py` (same test ids).
  `docs/DISTRIBUTION_DEVELOPMENT.md`: "Image build files". Inventory classification entries for the three new test files.

## Deviations and findings

- **The named builder cannot be created.** `docker buildx create --driver docker` fails: "additional instances of driver "docker" cannot be created". The "named buildx builder on the docker driver" of D19-8 is the implicit `default`
  builder of a fresh `DOCKER_CONFIG` pointed at the daemon with `DOCKER_HOST`; nothing was created in or removed from the user's builder store. S9 should use the same.
- Fresh `DOCKER_CONFIG` needed the `docker-buildx` plugin symlinked into its `cli-plugins` and `DOCKER_HOST=unix:///Users/shashank/.docker/run/docker.sock` (no `/var/run/docker.sock` on this Mac).
- Build cache: BuildKit records the layers of my builds in Docker Desktop's shared cache; there is no way to remove only mine without a prune, so it was left (no prune was run).
- `python:3.12-slim` was pulled by digest at the start (arm64, newly created), but another process' build later tagged the same image as `python:3.12-slim`; since another tag uses it, it was **not** removed.
  The pre-existing foreign containers/images in the snapshot diff (`mac-snapshot.diff`) are other processes' finished testcontainers runs.
- **Interim state: `make build-images` / `scripts/build_candidate_images.py` still run `docker build` from the repository root and do not work with these Dockerfiles** (they need the generated context). The next story moves the candidate
  builder onto the same context. `docs/SINGLE_CONTAINER.md` still shows the old `docker build ... .` line for the same reason.
- `DEBIAN_MIRROR` assumes a mirror with the Debian archive layout (`dists/<codename>`, `pool/`) signed by the Debian archive keys; the flat unsigned repository of the isolated proof environment will need a source line with its own key or `trusted=yes`
  (S9/S11).
- The locks were resolved in the trixie base: if a future release ships only newer manylinux tags, install on an older-glibc base would fail closed at the hash.
