### D08 shared-engine weakening: foreign images added during a run

The engine is shared with an outside workload that pulls images (`postgres:16.15`, `testcontainers/ryuk:0.14.0`, `node:24.22.2-bookworm-slim`; none used by E09,
none touched). The postflight (`scripts/service_lane.py::tolerated_foreign_images`, called from `verify_installed.py::service_postflight`) therefore tolerates a
foreign difference **only** when every changed category is images and their tag rows, no image is removed, replaced or re-tagged, containers, networks and volumes are
identical, and an added image is neither named, by tag or by repository digest, in a candidate repository (`ghcr.io/shashankshukla96/graph-loader-*`) nor carries the E09 owner label. The snapshot reads the image list once (ids, tags and repository digests come from one response and must
agree, every added id must appear in all three) and an existing image must keep its tags and digests. Added image
IDs, tags and digests go into the receipt (`service.postflight.foreign_images_added`) and the runner's summary line; anything else still fails. Controls: 19 in `tests/test_service_lane.py` (round-2 review: digest-only candidate image, digest gained or lost, disagreeing image tables, a changing image list read once; round-3 review: duplicate image ids and duplicate tag or digest rows are rejected before they become dictionaries).
The final lane run saw no foreign change, so this path is proven by the controls and by the red run above (which this rule would have tolerated), not by a green run that used it.
