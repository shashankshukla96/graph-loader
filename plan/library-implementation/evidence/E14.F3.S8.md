## Notes for the single-container docs (to fold in by the orchestrator after the docs lane merge)

* Stop: `docker stop` defaults to 10 s; the loaded fleet stopped in about 1 s here, but give it `-t 120`, compose `stop_grace_period` or `terminationGracePeriodSeconds` >= the stop budget plus margin.
* `--restart on-failure[:N]` for streams (a role loss exits 1, an ordered stop exits 0 and is not restarted); not `always`/`unless-stopped` for bulk jobs.
* Memory: `--memory` = `--memory-swap`; the sizing reads the container's limit; an OOM kill is reported once at group level (`stage=oom ... victim unknown`) and the run fails with exit 1 while the container survives; never a named victim. Docker's `OOMKilled` flag is true after such a kill even though the container itself kept running - do not use it as "the container was killed".
* The container was reachable by Neo4j/Kafka on the owned user-defined network by container name; the health port is bound with `--health-addr 0.0.0.0:8081` and published to loopback.
* After an abrupt end the restart waits for the old group members to expire before `/readyz` (the cells allow 300 s).
* arm64 has not been run (see above).
