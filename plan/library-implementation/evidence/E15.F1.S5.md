## Design as built

* **Durable acknowledgement**: `Outbox.append` writes the line to `<attempt>/status-outbox/events.<first seq>.jsonl` and `fsync`s it before returning; that is the moment `seq` is assigned (the journal protocol of S3). Nothing is buffered in memory on the healthy path, so the only events a `SIGKILL` can lose are ones not yet emitted (the plan's "window" is zero here; with a degraded outbox it is the in-memory queue).
* **Delivery**: a thread copies the outbox to the database in order, batches of 200, at least once; the database deduplicates by `(execution_id, seq)`; `ack.json` holds the highest delivered `seq` and snapshot revision, segments fully behind it are deleted. Database latency or failure never reaches the emitting thread (it retries with backoff in the background).
* **Snapshots are not queued**: only the newest is kept (`snapshot.json`), so overflow has no snapshots to drop first; the newest snapshot is delivered with the events and again at close.
* **Bound** (`GRAPH_LOADER_STATUS_OUTBOX_MB`, default 64; segments `..._SEGMENT_MB`, default 4): when undelivered events exceed it, the oldest whole segment is replaced by a gap record `{type: gap, seq: first missing, from_seq, to_seq, count, reason: outbox-overflow}` appended to `gaps.jsonl` and `fsync`ed BEFORE the segment is deleted (a control checks the order at the moment of deletion); the database receives it as an event; counter `outbox_overflow`, one log line per gap.
* **Unwritable outbox**: the journal degrades to a bounded in-memory queue, logs once, counts `outbox_unwritable`, writes `status-degraded.json` in the attempt directory if it can, and marks the execution `history_incomplete`; no gap is ever fabricated for what it cannot prove lost. Events already durable keep being delivered (the outbox stays readable; the watermark is then kept in memory).
* **Lock**: `flock` on `<attempt>/status-outbox.lock`, held by the live CLI for its lifetime, by `status-store flush` and by recovery while they deliver; released on exit however the process dies. `flush --wait N` waits for a live owner; recovery at the next `start` never waits (it skips an attempt that is locked).
* **Recovery** (`flush`, and a background thread at the next `start` over the same `--run-dir` base): truncates a torn tail to the last complete record, resolves the destination from `status-locator.json` and the credentials from the environment (never from the outbox), replays from the watermark, flags `history_incomplete` if the degraded marker exists. Interrupted replays resume; a batch delivered but not acknowledged is deduplicated.
* **Shutdown**: `close()` persists the newest snapshot, waits up to `GRAPH_LOADER_STATUS_SHUTDOWN_DEADLINE_S` (default 10) for delivery, then leaves the outbox on disk with one log line naming `status-store flush`; the lock is released.

## Acceptance

| Criterion | Evidence |
|---|---|
| Database down for the whole run, CLI `SIGKILL` once before and once after a batch's durable acknowledgement -> every acknowledged event delivered by `status-store flush`, no missing or duplicate `seq`, unacknowledged events absent with no `seq` | `test_every_acknowledged_event_is_delivered_by_flush_...[kill-after-ack|kill-before-write]` (real child, `SIGKILL`; the child reported 12 acks, the database gets seq 1-13, no unacknowledged text anywhere; a second flush delivers 0) |
| Overflow -> durable gap record with its seq range before deletion | `test_overflow_replaces_the_oldest_events_by_a_durable_gap_record_written_before_they_are_deleted` (the gap is on disk at the moment of each `unlink`; every `seq` is an event or inside a reported gap) and `test_the_database_receives_the_gap_as_an_event_...` (end to end, strict-schema valid) |
| Unwritable outbox then immediate `SIGKILL` -> no exact-gap claim, `history_incomplete` set on reconnect | `test_an_unwritable_outbox_then_sigkill_...` (the 3 in-memory events are gone, no gap row, execution `history_incomplete = true`) and the live variant `test_a_live_run_with_an_unwritable_outbox_degrades_once_...` (one log line, one counter, all events delivered from memory) |
| Concurrent `flush` and `start` recovery serialized by the lock | `test_concurrent_flushes_are_serialized_...` (4 threads: exactly one delivers all 41, the others 0), `test_a_live_owner_blocks_flush_and_start_recovery_until_it_lets_go`, `test_the_next_start_delivers_what_an_earlier_run_left_behind` |
| Torn tail recovered | `test_a_torn_tail_is_truncated_...` |
| Interrupted replay resumes idempotently | `test_an_interrupted_replay_resumes_from_the_watermark_...` (failure after the first batch; a delivered-but-unacknowledged batch is deduplicated) |
| Injected 2 s database latency leaves write timings unchanged within noise | `test_two_seconds_of_database_latency_leave_the_emit_path_unchanged`: 150 events + 150 total updates take the same time with and without a 2 s delay in every database write (printed by the test) |
| Shutdown deadline honoured | `test_close_honours_its_deadline_when_the_database_stays_down` (0.5 s deadline, returns False in under 3 s, 11 records still on disk, lock released) and the real-process `clean` cell |

Also: durable-acknowledgement ordering (`write` < last `fsync` < return), `seq` gap-free across segments and across a restart, a database that goes down and up in the middle is delivered in order with nothing lost, recovery of a non-SQL run is refused clearly, `flush` on an empty base says "nothing to deliver".

* `ruff check src tests` clean; Docker parity unchanged.
