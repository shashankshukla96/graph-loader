# E04.F2.S4 — Aggregate cleanup and retained ownership

The planner owns process handles before starting them. Cleanup shares one
absolute internal 10-second cutoff across stop delivery, heartbeat and all
join/terminate/kill phases. Failure signals all workers before joining; normal
stop delivery has a shared 100ms window. Interrupted writes cannot be followed
by a stop frame on the same stream. Endpoints close promptly and no IPC helper
is introduced. Unreaped workers retain owned lock/spill/topic state, with PID/
path diagnostics and original planning errors preserved through cleanup notes.

Focused installed-dev run: 186 passed in16.83s, raw log
`var/e04-validation-20261018/s4-tests.log`. Ruff for source/tests/examples/parity
and executable tools, plus whitespace, passed. Tests exercise the same six
public timeout/cancellation faults as S3 and assert final total time, child and
endpoint liveness, heartbeat absence, failure markers and reclaimed lock/spill.
Additional externally supervised real clients cover normal stop-write
backpressure, ordinary source failure, second process started before startup
raises, and four blocked workers for both cancellation and timeout. An inert
termination-resistant four-process fake advances a cleanup clock by every join:
aggregate joins are exactly10 seconds, all workers receive termination before
joins, kill escalates, diagnostics retain all PIDs and paths, and another close
does not get a new budget. Factory and convenience call cases retain both caller
and convenience topics while any child may remain alive; contender planners
refuse the retained lock. Fake-owned resources are manually recovered only after
assertions; the fake creates no OS process.

The inherited single-worker abort test now asserts bounded join values rather
than an implementation-specific first join of exactly5 seconds: the shared
schedule deliberately replaces that per-worker grace. Its original prevention
of a30-second wait remains. Real child faults each have a separate hard-deadline
supervisor and owned emergency cleanup, in addition to pytest's outer timeout.
