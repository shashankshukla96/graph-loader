## Design as built

* Tables: `schema_version`, `executions`, `execution_activities`, `execution_phases` (new: phases are an S1 addition), `execution_labels`, `execution_types` (progress fields as JSON), `execution_roles`, `execution_events`. `execution_roles` is keyed `(execution_id, incarnation)` (an incarnation is unique), not the four-column key of the first design sketch; `role` and `replica` are columns. No foreign keys: a failed write of one table cannot block another and `prune` deletes explicitly, children first. Timestamps are `timestamptz` (Grafana-friendly); JSON columns use SQLAlchemy `JSON` (`outcome` and `last_error` store SQL `NULL`). Schema `graph_loader` on PostgreSQL (`GRAPH_LOADER_STATUS_SCHEMA`), none on SQLite.
* Snapshot: ONE transaction; the row is inserted or updated only `WHERE revision < new`; an older or equal revision returns `False` and changes nothing; children are replaced inside the same transaction; `read_status` rebuilds the exact snapshot from the tables (round-trip equality is tested for a stream and a planned run).
* Events: idempotent insert; same key and same SHA-256 skipped; different payload -> `EventConflict`, nothing of that batch is written, `status_store_errors_total{reason="event_conflict"}` counted.
* Migrations: `status-store migrate` is idempotent; `start` refuses a missing or older schema (exit 1, message names `status-store migrate` and `--status-store-auto-migrate`) and a newer one; `--status-store-auto-migrate` / `GRAPH_LOADER_STATUS_AUTO_MIGRATE=1` migrates at start. An unreachable database at start is only a warning: the run goes on.
* `prune --older-than 30d` deletes finished executions (terminal state, `finished_at` before the cutoff) with all their rows; running, stopping and starting ones are never touched, however old.
* Connection URL only from `GRAPH_LOADER_STATUS_DB_URL` (never a command-line argument); every driver message passes through `_scrub` (URL, password, `password=...`).
* Credentials: a PostgreSQL password may come from the URL, `PGPASSWORD`, `.pgpass` or a service file (libpq/psycopg); the locator keeps the URL without user, password or password-like parameters; a reader prefers `GRAPH_LOADER_STATUS_DB_URL` only if it names the same database as the locator.
* `SqlJournal` (in-memory queue, background writer) is S4's interim delivery path; S5's outbox replaces it in the CLI. Only the CLI connects; roles never receive the URL.
