## What was built

1. **`orchestrator/role_launch.py` (new, docker-free).** The `run_global_batch_clock`, `run_bucket_lease_server`, `run_planned_dispatcher`, `run_planned_edge_writers`, `run_edge_loader`, `run_retry_consumer`
   and `run_node_loader` builders were moved out of `DockerService` into `RoleLauncher`, with the metrics/label/port helpers and `_launch_all`, **unchanged** (text move; only `load_schema(config_path)` became the `self._schema(...)` hook and
   the rollback function became `self._rollback(auto_remove)`). `DockerService(RoleLauncher)` keeps the Docker-only parts (client, images, preflight, `_run_container` -> `containers.run`, the stop hold, discovery, the IP-based address helpers) and
   re-exports every moved name, so `docker_service.X` keeps working for callers and tests. One builder, two backends: process mode inherits each role's exact command, environment, replica naming and labels from the Docker code path.
2. **`orchestrator/process_service.py` (new) - `ProcessService(RoleLauncher)`**, the process backend of the `Runtime` protocol. Its `_run_container` turns the Docker launch parameters into `ProcessRuntime.spawn`:
   a bind mount `host -> /app/...` becomes a path substitution in the command and environment; Docker-network service defaults (`bolt://neo4j:7687`, `kafka:29092`) become the CLI's own `NEO4J_URI` / `KAFKA_BOOTSTRAP_SERVERS` unless `LOADER_*` was set;
   `image`/`init`/`network` are dropped; `entrypoint` -> module; `cpuset_cpus` -> `LOADER_CPUSET`; `remove` -> auto-remove; lease server and dispatcher get `--host 127.0.0.1` and a loopback port reserved per `(module, run id)`
   (a replacement lease server reuses the port, so `GRAPH_LOADER_BUCKET_LEASE_ADDR` stays valid); `bucket_lease_address` / `planned_dispatcher_addresses` return `127.0.0.1:<ready port>`;
   discovery (`list_run_containers`, `list_node_loaders`, `stop_node_loaders`) works on this CLI's handles; images are no-ops; `preflight_topology` checks Linux >= 5.3, pidfd, `/proc`, writable run directories and that an isolated child interpreter can import the package (no Docker call).
   `planner_supervision()` + `add_pre_signal_hook` wire S3 (planner workers follow the CLI; `planner.close` runs before any group signal). `close()` writes a `cli-exit` record and kills leftovers.
3. **CLI** (`--runtime process`): the S1 refusal is replaced by real behaviour. `start` registers the CLI in the registry, closes the runtime last, passes `PlannerSupervision` to the planner and registers `planner.close` as the pre-signal hook.
   `--network` (even at its default value, tracked by an `_ExplicitStore` action) and `--skip-image-build` are rejected with `... applies to Docker containers and is not accepted with --runtime process`; macOS/non-Linux is refused up front for `start/stop/status`
   (`the process runtime is supported on Linux only (this is Darwin); use --runtime docker`). `stop` and `status` work from a second shell through the run's registry: `stop` signals the registered CLI through a pidfd after re-verifying its start time and boot id,
   `stop --loader L` signals only that label's registered node loaders; `status` lists node loaders in the Docker format from the registry. They take `--run-dir DIR` (an attempt directory, or the base given to `start`; exactly one live run under a base is picked, otherwise an explicit directory is required).
   `replay-dlq` needs no runtime and behaves identically.
4. Registry `started` records now carry the role's labels (component, node_label...), which is what makes label-scoped `stop` and `status` possible from another shell.
