## Design as built

* **Journal protocol** (shared with the S5 outbox): `append(make_event) -> event`; the store chooses `seq` and calls `make_event(seq)`, so `seq` is assigned at the moment the line is durably written (write + `fsync`), gap-free in the file. Events recorded before the store exists (`execution.started`) are replayed into it in order and must come back with the same `seq`.
* **Files in the attempt directory**: `status-locator.json`; `status.json` (temp + `fsync` + `rename`, at most once per `GRAPH_LOADER_STATUS_SNAPSHOT_INTERVAL_S`, default 1 s, plus a synchronous write of the newest snapshot at close, so the terminal state is always on disk); event segments `events.<first seq, 12 digits>.jsonl`, rotating at `GRAPH_LOADER_STATUS_EVENT_FILE_MB` (default 8) keeping `GRAPH_LOADER_STATUS_EVENT_FILES` (default 8). Naming a segment by its first `seq` (instead of renaming `events.jsonl` to `.1`, `.2`) lets a follower track a position across rotation without inode games; **this differs from the plan's literal `events.jsonl`**.
* **Locator**: `{kind: status-locator, store, execution_id, run_id, created_at, files | database{url without credentials, schema}}`; rewritten when the run id is assigned; written for both stores; the database URL loses its user information and any `password`-like query parameter.
* **Accessor**: `read_status(location=None, *, execution_id=None, validate=True)` and `iter_events(location=None, *, execution_id=None, follow=False, start_seq=1, poll_interval, stop, idle_timeout, validate=True)`. `location` = attempt directory, locator file, or a base directory (newest attempt, or the one named by `execution_id`). Validated against the PUBLISHED open schemas. A torn final line is not an event; rotated-away history is one `gap` event (`reason: history-rotated`), a hole in the middle is a `gap` (`reason: missing`), a damaged complete line is `StatusDataError`. `follow` ends after `execution.finished`, on `stop()`, or after `idle_timeout`. A store with no registered reader (`sql` until S4) is `StatusStoreError` naming the extras.
* **Failure never reaches the load**: a failed write disables the store (one log line, `history_incomplete: true`, the tracker continues with in-memory `seq`); a base that cannot be created or a locator that cannot be written disables status for the run with one line.
* **`--status-store {json,sql}` / `GRAPH_LOADER_STATUS_STORE`** exists now; `sql` writes its locator (credential-free) and then says "not available in this build", status disabled, until S4 registers the SQL store.

## Decision to confirm: where the attempt directory is created

The orchestrator asked for the attempt directory and locator to be created from the arguments alone, before schema load. Existing tests pin the opposite for rejected input: `test_runtime_paths.py::test_missing_schema_and_invalid_numeric_flags_do_not_create_state` and `::test_invalid_plan_flags_fail_before_schema_state_metrics_and_dispatch` (13 cases) require that an invalid flag, or a missing schema file, creates **no** state under `--run-dir` (they failed when I created it first; 14 new failures in the full run). So the store is opened **after the arguments are validated and the schema file is known to exist, immediately before `load_schema`**: a schema-load failure (unreadable or invalid schema, which is the acceptance case) is recorded in the attempt directory with a terminal `failed` status, but a rejected flag or a nonexistent schema path leaves nothing on disk (their execution exists in memory only). If the orchestrator wants those recorded too, the E05 tests would have to change; I did not change them.
Docker parity and E14 process behaviour: unchanged (`prepare_run` reuses the directory; no Docker call, name, mount or environment differs; parity and process tests green).
