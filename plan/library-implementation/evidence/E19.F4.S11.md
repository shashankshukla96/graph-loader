## Topology differences from S9/S10 (harness only)

- **The runner now shares the inner daemon's network namespace** (`up --runner-netns`): the docker runtime's planned-edges dispatcher publishes its control port on the loopback of the CLI's host (`127.0.0.1:<port>`), so a CLI in a separate network namespace from its Docker daemon ("a remote Docker host") cannot reach it (red run a: `dispatcher 127.0.0.1:32770 unreachable: Connection refused`). Sharing the namespace is what "the CLI's host is the Docker host" means. Neo4j and Kafka publish their client ports (`7687`, `9092`) on that namespace only (the inner daemon's, not the host's: the listening ports of the real host are unchanged: `22 53 631 3389 5432 7474 7687 8080 9092 9101`, all pre-existing); Kafka advertises `dind:9092` externally and `kafka:29092` internally.
- Memory limits re-cut so that the process runtime fits: its sizing rule needs about 1,030 MiB of headroom for the CLI, four roles and one planner (red run b: `the memory limit leaves 0 MiB for the planner` at 640 MB). Runner **1,500 MB**, dind **3,180 MB**, the small services unchanged: sum **5,112 MB of 5,120**. The dind peak sampled during all loads was **2,666 MiB**.
- The big seed images are released from the shared daemon (by the ownership rules) as soon as the registry holds them (Neo4j 1.6 GB, the htpasswd image), which brought the disk to **9.87 GB of 10** (work directory 184 MB + owned volumes 8,290 MB + new images on the shared daemon 1,391 MB). Without that the first run measured 12 GB and was stopped by the budget check.
