# E19.F2.S3 — `GRAPH_LOADER_IMAGE_REGISTRY` (evidence)

Date 2026-11-03. Worktree `graph-loader-e19`. Nothing committed. Mac only, CPython 3.12, `pytest==9.1.1`. Logs in `E19.F2.S3-logs/`.

## Change

- `src/neo4j_graph_loader/_images.py`: `registry_prefix()` (grammar `host[:port](/lowercase-component)*`, at most 255 characters, no scheme, `@`, tag, digest, whitespace
  or empty component), `valid_reference()` (full reference `name[:tag][@algo:hex]`; a bare `@` before the digest is userinfo and is refused), and `image_reference()`:
  per-role variable, else `GRAPH_LOADER_IMAGE_REGISTRY` (empty = unset), else `ghcr.io/neburyx`. `ImageSelectionError` moved above them. An invalid prefix raises
  `invalid GRAPH_LOADER_IMAGE_REGISTRY: use host[:port] and lowercase path components, with no scheme, credentials, tag, digest, spaces or trailing slash` and never echoes the value.
- The existing per-role pattern (`[A-Za-z0-9._:/@-]`) accepted `user:password@host/image`; `resolve()` now uses `valid_reference()`, still accepting tags and `@sha256:` digests.
- Wiring needed no other change: `ImageSelection.__init__` builds all four references (so `DockerService(...)` refuses a bad prefix before any daemon call, and `start` logs
  `stage=image reason=…` and exits 1); the process runtime never calls `image_reference` and ignores the variable; `cli` is covered by the same function.
- Docs: `docs/CLI.md` (variable row and grammar paragraph), `docs/DOCKER_EXECUTION.md` ("Your own registry"), `docs/SINGLE_CONTAINER.md`, `docs/USAGE.md` (row edited in place) and `README.md` (sentence in place),
  so no yaml snippet line moved (the snippet-id test is green).

## Notes

- A prefix such as `myorg` (no dot, no port) is accepted as a host name; Docker treats it as a Docker Hub namespace. The guide (S11) should say a registry prefix should contain a dot or a port.
- `GRAPH_LOADER_IMAGE_REGISTRY` does not rewrite a per-role override or an `--image` style flag (there is none); `build_candidate_images.py` keeps its own namespace constant (S6 unifies the build path).
