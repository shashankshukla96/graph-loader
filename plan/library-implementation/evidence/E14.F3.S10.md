### The two red causes

1. **Start-up revoke - a known product limit, tracked as E18 (later version), made likely by the test broker's delay of 0.** After a restart that waited for the old group's members, the first Customer replica's JoinGroup completes alone (delay 0) and it already has writes in flight when the sibling joins 10 ms later and a partition is revoked. Incarnation 5 (after the retry-consumer kill): `Dropped 2 uncommitted prefetched message(s) of revoked partitions`, `Kafka partitions revoked with unresolved work label=Customer partitions=[...customers, 2]`, 6 writes already done, replica start ticks 01:55:54.560 / .570, exit 1.88 s after start, `node loader exited while the stream run was active` -> fleet exit 1 -> the harness restarted it; no data impact. The same happened once in the first full run (incarnation 4, 1.86 s after start). Hypotheses tested and refuted: a stale member expiring (the old Customer loaders exited 0 after closing their consumers; the CLI's member check listed only the SIGKILLed role's group) and a staggered start (start gap -0.01 .. +0.01 s over 9 incarnations vs 24-64 ms for Docker containers in E13 S1/S2). It is not process-runtime specific; Docker mode has the same loader code. Documented as a known limit in `docs/USAGE.md` section 12 and `docs/PROCESS_RUNTIME.md` section 10 (trigger, effect, mitigations).
2. **Harness Kafka-window bug (fixed offline in the harness, not yet proven live).** Incarnation 2's exit is the one *caused by* the injected Kafka broker restart (broker refused, `member_check_failed`, an edge loader exited, then the node-loader supervision line). The new `end_windows()` I added to stop E13's explanation window from absorbing later exits closed the window as soon as the fleet reported ready after the broker returned - before the fleet had noticed the outage - so this legitimate exit was counted as unexplained. Fixed: the Kafka fault waits for the next fleet generation to be ready (or 150 s with the fleet still up) before closing its window; 108 harness tests pass. The live proof is E13's rerun on 0.1.0a2.
