## Design notes

- Locks are generated by `pip-compile --generate-hashes` (pip-tools 7.6.2, installed only inside the container) with `--only-binary=:all:` in `python:3.12-slim` by digest
  (`sha256:b18b261e…ab30`, CPython 3.12.16, Debian trixie) on `--platform linux/<arch>`. pip-compile lists the hashes of *every* file of a release (one dependency had 171), so the tool
  then runs `pip download --no-deps --only-binary=:all:` for the pins in the same container and keeps, per pin, only the hash of the wheel pip chose on that platform, after checking it is
  one of the published hashes. Each pin therefore has exactly one hash: a wheel for another architecture is refused by hash as well as by tag.
- Each lock records platform, Python, base image, `sha256` of `requirements.txt`, generator versions and `content-sha256` of its body. Editing a pin or hash is detected offline.
- Lock location: `image-locks/` for now (not package data). `pyproject.toml`, `MANIFEST.in` and the two artifact validators are S6's change surface; putting the files under the package
  tree now makes the strict artifact verifier fail (`test_artifact_contract`), so S6 moves them.
- Containers are created, started and removed by recorded id (`--user`, `--cap-drop ALL`, `no-new-privileges`, 1 GB, 2 CPUs, owner label); no force, no prune. The unit test records the
  exact docker verbs.
