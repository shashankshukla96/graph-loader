## What was built

- `src/neo4j_graph_loader/_child.py` — `python -I -u -m neo4j_graph_loader._child <module> [args]`: applies `LOADER_CPUSET` (`os.sched_setaffinity`), adopts the
  control socket, starts the lifeline thread, runs the role with `runpy.run_module(..., run_name="__main__")` so each role's own early handlers, logging set-up
  and exit codes are unchanged. Only `neo4j_graph_loader.*` modules are accepted; `script:<path>` is a test seam that needs `GRAPH_LOADER_CHILD_ALLOW_SCRIPT=1`.
- `src/neo4j_graph_loader/_child_protocol.py` — `runtime_ready(bound_ports=None)`; a no-op unless `_child` installed a channel (Docker mode and direct runs unaffected).
  Hook added to all seven roles, after the SIGTERM handler is installed and the endpoints are bound: `node_loader`, `edge_loader`, `planned_writer`, `retry_consumer`,
  `clock_runner` (after the metrics server start) and `planned_dispatcher`, `lease_server` (after the control server bound; they report `{"control": port}`).
- `src/neo4j_graph_loader/orchestrator/run_registry.py` — append-only JSONL (`<crc32 hex> <json>`), `fsync` per record; torn final line ignored, interior damage raises;
  after a failed/short write the writer truncates back to the last complete record or marks itself broken and refuses appends; `fold`, `cli_record`, process identity
  (Linux `/proc/<pid>/stat` field 22 + `boot_id`; on hosts without `/proc`, `ps lstart` + `kern.boottime`, development only), `signal_registered_cli` (pidfd opened first,
  identity verified after, then the signal goes through the pidfd; `StaleRegistry` otherwise).
- `src/neo4j_graph_loader/orchestrator/process_runtime.py` — `ProcessRuntime.spawn(role, module, args, env, ...)` → `ProcessHandle` (`Handle` protocol: `name`, `id`,
  `labels`, `status`, `attrs` with `OOMKilled: None`, `reload`, `top`, `logs` in all forms, `stop(timeout)` = SIGTERM, grace, SIGKILL, `remove(force)`, `hold_for_stop`,
  `stop_ready`, `kill`, `wait`). Start: `start_new_session`, `close_fds`, `pass_fds=(control,)`, `cwd=<run>/work/<role>-<n>`, environment = allowlist
  (`PATH HOME LANG LC_ALL TZ TMPDIR`) + exactly the role's variables. One reaper thread per child is the single owner of the exit and writes the one terminal `exit`
  receipt; negative return codes become `128+n`; stdout/stderr go through a size-capped (rotating, one predecessor) log pump to `<run>/logs/<role>-<n>.log`.
  Signals go through a pidfd opened immediately after the spawn (Linux), else through the unreaped `Popen`; a reaped child is never signalled; `killpg` only while the leader is unreaped.
  Readiness: `wait_ready` fails the launch if the child exits first (message includes code and the last output) or is silent past the timeout (child SIGKILLed first).
  A failed `started` registry write kills the child and fails the launch. The role-specific launchers (`run_node_loader` & co.) are S4; this module is the lifecycle layer under them.
- `src/neo4j_graph_loader/orchestrator/runtime.py` — `wait_until_stop_signal_ready(handle)` now lives behind the `Handle` protocol (`hold_for_stop`): a handle class that defines
  it supplies its own hold (`DockerHandle` delegates to the unchanged Docker hold, `ProcessHandle` waits for readiness); doubles without it get the Docker hold.
  `cli.py` imports it from `runtime` (it no longer imports `docker_service` for it). **Docker-mode parity unchanged** (golden still equal, 45 parity/boundary tests pass).

## Findings made while building

1. **Lifeline bug found by the kill -9 test (fixed).** After the CLI dies, a role's stdout/stderr pipe has no reader. The wrapper's own `stderr` warning raised
   `BrokenPipeError` in the lifeline thread *before* it sent SIGTERM, so nothing stopped (idle and busy children survived on the Mac). Fix: on EOF the wrapper points fds 1 and 2
   at `/dev/null` first, then SIGTERMs itself (so a role's graceful shutdown logging cannot hit a broken pipe either), then hard-exits after the deadline. Both lifeline tests are red without it and green with it.
2. **Roles that die of a broken pipe** is the general consequence of log pipes outliving the CLI; S5's relay must keep the pump independent of the CLI's stdout.
3. The Docker mode's 1.0 s "floor" before a stop is the interpreter-import window; the process runtime needs none because readiness is an explicit report after the handler is installed.

### Defects the host found (red runs kept: `logs/pytest-s2-s3.log`, `logs/pytest-s2-s3-RED-fdleak.log`)

1. **Ready-then-exit race (fixed).** On Linux a role that reports ready and exits at once (`quick`) lost the race between the reaper (exit visible) and the control reader (ready not yet processed), so the
   launch was reported as "exited with code 0 before it was ready". The reaper now joins the control reader (which ends at EOF) before the exit becomes visible; `test_ready_then_immediate_exit_is_not_a_launch_failure` (20 launches) covers it.
2. **File-descriptor leak (fixed).** The 100-iteration loop died with `OSError: Too many open files` (ulimit 1024) at ~940 launches: each child's stdout pipe was never closed. The log pump now closes it;
   `test_a_finished_child_leaves_no_open_descriptors_behind` (25 launches, descriptor count flat) is Linux-only and passed after the fix. A long-lived CLI that restarts roles would have hit this.
