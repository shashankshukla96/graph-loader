# E19.F2.S6 — `graph-loader images build`, provenance and the unified candidate builder (evidence)

Date 2026-11-03. Worktree `graph-loader-e19`. Nothing committed. Mac with Docker Desktop (already running), arm64; same rules as S5 (fresh `DOCKER_CONFIG`, owned tags only, no prune,
no host sitting). Logs in `E19.F2.S6-logs/`.

## Change

- **Package data.** The four Dockerfiles moved to `src/neo4j_graph_loader/image_build/dockerfiles/` and the two locks to `image_build/locks/`; `pyproject.toml` (`package-data`) and `MANIFEST.in` ship them in the wheel
  and the sdist. The finite resource list of the strict artifact verifier (`scripts/verify_artifacts.py` `RESOURCE_FILES`, 19 → 25) and the installed runner's payload allowlist
  (`scripts/verify_installed.py` `IMAGE_BUILD_RESOURCES`) grow by exactly those six files; `test_artifact_contract.py` keeps the two equal and builds a real wheel and sdist with them. The root `.dockerignore` is gone (the context is generated).
- **Build core** `neo4j_graph_loader/image_build/builder.py` (`Settings`, `build`): validation and refusals; the sanitized docker environment (a fresh `DOCKER_CONFIG` with a `cli-plugins/docker-buildx` link, `DOCKER_HOST` = the current context's
  local socket, `PATH`/`HOME` only; no proxy or `PIP_*` of the caller); **scoped registry logins** (only the `auths`/`credHelpers` entries of the base image's registry and the target registry; a global `credsStore` becomes a per-registry
  `credHelpers` entry; no proxy, plugin or context setting is copied; the temporary config is removed afterwards); base image resolved to a digest with `buildx imagetools inspect`; the context generated from package data + the wheel + the wheelhouse;
  `docker buildx build` per role with `--secret id=pip_index` for `--pip-index-secret`; label and entrypoint checks on the built image; Debian package versions of the CLI image; `docker push` with the same config; manifest writer. The Docker SDK is not used.
- **Command** `graph-loader images build` with `--registry`, `--package-version`, `--package-wheel`, `--base-image`, `--pip-index-url | --pip-index-secret | --wheelhouse`, `--pip-ca-bundle`, `--debian-mirror`, `--proxy`, `--docker-config`,
  `--tag-suffix`, `--push`, `--dry-run`, `--output`, `--replace`. Documented in `docs/CLI.md` ("images build"), `DOCKER_EXECUTION.md`, `SINGLE_CONTAINER.md` (the new build path replaces the old `docker build .` line) and `DISTRIBUTION_DEVELOPMENT.md`.
  `tests/test_docker_parity.py` normalizes the new top-level command like E15's (the a1 golden is unchanged).
- **Provenance manifest (D19-6)** `images.json`, schema `graph-loader-image-manifest/2`: recipe version, Dockerfile and install-helper hashes, requested and resolved base image, platform, the package wheel file name and sha256, the lock file and sha256, every dependency
  artifact sha256 (`dependency_sha256`), the build arguments without secrets (the plain index URL is not recorded), the Debian package versions, and per image the id, labels, entrypoint, reference, digest after a push and the recorded command (the secret is a file: `src=<secret file>`).
- **Consumers.** `scripts/installed_service.py`: `wheel_binding(wheel)` reads the build files out of the wheel; `validate_images(path, *, version, wheel, client)` binds the manifest to the wheel under test (wheel sha256, Dockerfile and helper hashes, lock sha256, dependency
  hashes, a digest-resolved base) in addition to the existing identity checks. `scripts/verify_installed.py` `preflight_service_images(..., wheel=)` (used by every service lane) replaces the checkout source-hash comparison with that binding and also requires the wheel's
  build files to equal its frozen payload. The source-file hash comparison (`build_inputs`, `input_sha256`) is gone.
- **Candidate builder** `scripts/build_candidate_images.py` now builds (or takes with `--wheel`) the candidate wheel and runs the same core with `bind_to_installed=False`, tag suffix required, never pushing; dependencies from `--wheelhouse` (a copy gets the candidate wheel) or an index (default public PyPI).
  `make build-images` passes `CANDIDATE_WHEELHOUSE` / `CANDIDATE_INDEX` and also checks the locks.
- Tests: `tests/test_image_builder.py` (49) with a recording stand-in for the docker CLI; assertions updated (same ids) in `test_installed_service.py`, `test_candidate_images.py`, `test_artifact_contract.py`, `test_docker_parity.py`, the Dockerfile tests; new
  `wheel_binding` and manifest-control tests in `test_installed_service.py` (10 new ids). `tests/test_docker_build.py` (integration) now builds through the candidate builder.

## Changelog items for the 0.1.0a2 freeze

- New command `graph-loader images build` (and the shared build core); needs Docker with buildx.
- Images are now installed from a hashed dependency lock per platform with `--require-hashes --only-binary=:all:` (same versions as 0.1.0a1's images today); **image content changed: `/app` now holds only `config/graph_schema.yaml`
  (node, edge and CLI images; none in the clock image)** — the old images also carried the whole source tree, `build/`, `pyproject.toml`, `requirements.txt`, `PACKAGE_README.md`, `LICENSE`, `MANIFEST.in`, `config/neo4j`, `config/support-matrix` and (CLI) `.env.example`. The runtime reads nothing of those (it uses mounts).
- `GRAPH_LOADER_IMAGE_REGISTRY` (S3); per-role references with credentials are refused (S3).
- Package data: the four Dockerfiles, two locks and `install.py`/`lockfile.py`/`builder.py` modules (`neo4j_graph_loader/image_build/`); wheel payload and artifact contract change accordingly.
- `make build-images` builds from a generated context (wheel + lock) and takes `CANDIDATE_WHEELHOUSE` / `CANDIDATE_INDEX`; the manifest schema is `graph-loader-image-manifest/2` (`input_sha256` is gone).
