Dispatcher protocol: `STATUS.by_type`. Nothing else in `status`/event/metric contracts changed.

## Docker runtime: the one additive Docker-mode change (approved)

Conditions from the orchestrator, and how each is met:
* Exactly three NEW keys per role launch, everything else byte-identical: `GRAPH_LOADER_EXECUTION_ID`, `GRAPH_LOADER_INCARNATION`, `GRAPH_LOADER_STATUS_SNAPSHOT_DIR=/app/write-timings/<execution_id>/<incarnation>`. `tests/golden/docker_parity_0.1.0a2.json` is new; the 0.1.0a1 golden is untouched; `test_a2_differs_from_a1_by_exactly_the_three_status_env_keys_per_role_launch` proves `strip_status_env(a2) == a1` for every scenario (outcome and trace, byte for byte) and that every launch with the timing mount has exactly the three keys; three controls (a fourth key, a missing key, an added mount) fail the a2 comparison. The existing parity tests still compare against the a1 golden after stripping the three keys; 17 scenarios x a2 comparisons are new. Diff for the orchestrator: `side-session-notes/.../e15-s2-parity-diff.md` (sent).
* No new mount: the directory is inside the existing `/app/write-timings` bind. Roles without a timing mount: none under `graph-loader start` (`prepare_run` always provides the timing directory); only direct `DockerService` use without a run directory (2 parity scenarios, 7 launches) has none, and gets no keys; a tracked launch without the mount is recorded by container id and writes no snapshots (test).
* Present on every tracked launch whatever the status-store setting (the tracker exists for every `start`); a role simply writes its snapshot, the store is a CLI matter.
* Process runtime: same keys, registry incarnation reused; the E14 process tests are green. `GRAPH_LOADER_STATUS_INTERVAL_S` is passed through only if the operator set it (never in the deterministic trace).
* The incarnation is generated before the launch (`DockerService._run_container`) and equals the tracker's role incarnation (`test_a_docker_launch_with_the_timing_mount_gets_exactly_three_new_env_keys_...`).
* S8 reuses these keys for metric labels and adds no further Docker change.

## Not covered / notes

* No live Docker, Kafka or Neo4j here: the Docker transport is proven by the recorded call (env keys, existing mount) and the process runtime's real children; the live Docker proof is S12 on the host.
