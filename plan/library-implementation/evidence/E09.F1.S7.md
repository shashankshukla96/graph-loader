## Weakenings relative to the approved plan

1. **AC4 not met** (accepted by the user): no daemon-compatible fence, retained namespaces, dedicated daemon with witnessed continuity, or durable broker. Same-user processes and `docker` group members reach the socket. **The installed CLI under test itself holds engine-wide socket authority**; the only guard is name/label ownership plus the before/after snapshot. Network and volume removal only by recorded ID after owner-label verification; real network-removal authority stays closed.
2. **Application containers are observed, not authorised**: no product adapter (no product change), no durable intent before the daemon create, a lost create cannot be settled. Completeness is shown for candidate-image creations (created == observed) up to a stream barrier, not for containers from other images; the barrier proves the stream is current relative to its own events, not that Docker publishes events of different types in causal order or loses none (Docker 29 ordering is not independently documented here; per-run `observer.json` retains the barrier events). Ownership of unlabelled containers is provenance by image, network and non-pre-existence, not creation provenance; same-user label impersonation and the inspect/remove interval remain within the accepted unfenced-substrate limits.
3. **Supervision**: the CLI runs in its own session; on a runner timeout only the pytest process group is killed and the CLI is reclaimed by the runner's provenance-based owned-process cleanup (Python processes only). No watchdog independent of the runner host process; no pidfd/creation fencing.
4. **Query-log continuity is by observed ID contiguity**, proven only on the harness-injected non-rolling structured JSON appender, **not** on the shipped rolling `config/neo4j/server-logs.xml` text log (only its template hash is an input). Rotation is rejected, not covered by a rolling-log reader. Captures are capped at 8 MiB and re-read in full: fine for the tiny smoke only. Source-to-sink emission is unproven.
5. H4's plan digest is recomputed from the plan file; S1 owns independent prediction.
6. H5 proves outage/kill controls on Neo4j, Kafka and owned helper containers, not application failure semantics (S1/S5).
7. **Dependencies float**: the lane venv resolves PyPI versions (recorded in `install.log`); the candidate image build fetched dependencies from PyPI; `neo4j:5-enterprise` is a floating tag with its ID recorded.
8. The fenced-broker modules were deleted in the 2026-10-31 plan reset (D08); they were unused by this lane. `test_service_cli_remains_closed_until_controller_and_image_preflight_exist` kept its frozen ID but now asserts that a failed image preflight stops the lane before any output.
9. The shared-runner changes (guard loader, service branch, `service = None`) were exercised on the Debian host lane and, in round 2, on all eight installed unit lanes on the Mac (macOS, not Linux). The E08 process envelope passed on macOS only, not on the Linux host.
10. Kill-during-create recovery is simulated (truncated registry, unrecorded intent), not produced by killing a live controller.
11. The reaper's removal-error path is now also exercised live (a stray's active endpoint blocks network removal, `reaper-control-5`); inspect and transport errors are exercised with fakes only.
12. (Round 4 minor, not repaired) Barrier volume names are `e09-<owner>-barrier-<n>` per observer instance: two observers for one owner could consume each other's cached marker events. The lane uses one observer per owner; add a nonce before supporting more.
13. (Round 4 minor, not repaired) `read_registry` treats malformed and non-dict JSON rows as corrupt and continues, but a JSON object without an `owner` key makes the whole registry fail validation (fail-closed, never a false clean). Also, `images=… or None` in the postflight falls back to the network-only rule if image metadata were ever empty; the runner always supplies four validated candidate IDs.
14. A foreign container created during the run from a candidate image, attached to the owned network and unlabelled, is indistinguishable from the CLI's own: inherent to the accepted unfenced provenance model.
