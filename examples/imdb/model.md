# IMDb graph model

`graph_schema.yaml` currently declares the following node types, all of which
are generated by `build_subset.py` and can be published by the node-only
example:

| Node | IMDb source |
| --- | --- |
| Title, TitleType, Genre | `title.basics.tsv` |
| Person, Profession | `name.basics.tsv` |
| Character, credit facts | `title.principals.tsv` |
| AlternativeTitle, Region, Language | `title.akas.tsv` |
| Rating | `title.ratings.tsv` |

The subset generates and publishes the relationship model below. Each TSV row
is converted to the production edge-event envelope using the endpoint key
properties declared in `graph_schema.yaml`:

- `HAS_GENRE`, `HAS_TITLE_TYPE`
- `HAS_PROFESSION`, `KNOWN_FOR`
- `CREDITED_ON`, `ACTED_IN`, `PLAYED`
- `DIRECTED`, `WROTE`
- `EPISODE_OF`
- `HAS_ALTERNATIVE_TITLE`, `AVAILABLE_IN_REGION`, `IN_LANGUAGE`
- `HAS_RATING`

IMDb's `\\N` missing-value sentinel remains in the filtered `source/` TSV
copies.  Generated graph TSVs convert that sentinel to an empty value, so the
loader does not create a literal `\\N` property.
